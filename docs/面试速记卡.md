## ① 整体架构（先讲清楚这个）

**为什么 LangGraph 而非函数链**：图的是 checkpoint 和回放。函数链要我手写状态快照+中间恢复=重造 LangGraph。并行靠返回元组（`app/query_process/agent/main_graph.py:64`）、分支靠条件路由函数、状态自动落 Postgres。

**三能力落点**：
- 可观测 = `observe_node` 装饰器统一包裹（span+事件+快照+耗时），业务节点零污染；门面 `app/core/observability.py`，开关关掉自动 Noop。
- 可测试 = 节点是 `state→partial dict` 纯函数；评测复用生产图 + `eval_mode` 不写历史；回放 mock 模式复测线上输入。
- 可灰度 = 入口开关（`use_standard_understanding`）+ 路由开关（planner/rerank_gate/evidence_gate），默认全 False，开流量前先开代码。

**状态传递**：共享 TypedDict + 节点返回增量自动 merge；默认值深拷贝工厂函数；并行字段各写各的，只有 `retrieval_diagnostics` 用 `merge_retrieval_diagnostics` reducer 合并（`app/query_process/agent/state.py:89`）。

## ② 五条链路 · 亮点 + 坑 + 答法

### 导入/版本治理
- 亮点：chunk_hash（故意不含 index）→ 中间插章节不触发连锁重算；pending→CAS active 激活；查询侧指针过滤"插入即 active"。
- 坑：版本号先查后 +1 有竞态 → 修复用 `findOneAndUpdate($inc)` 原子自增。
- 金句：自增防撞号 → CAS 防脏激活 → cleanup 防残留，三件套。

### 检索优化/三级门控
- 亮点：计划器 + RRF 融合 + Rerank + Evidence Gate（不够就拒答，不调 LLM）。
- 坑1：计划器 top_k/权重没接线（硬编码 limit=5）→ 承认 + 契约测试补。
- 坑2：分数域错配（跳过 Rerank 后 rrf_score≈0.016 撞 0.45 阈值误拒答）→ 已修：跳过精排只做数量+实体门控。
- 金句：分数不是数字，是分布的抽样；比大小前先确认同一把尺子。

### 可观测（王牌）
- 亮点：OTel trace + 35 指标 + 20 告警 + 5 Grafana + Langfuse + 快照/回放/diff。
- 答法：告警 → trace_id → timeline → `/debug/replay/node` 重放；mock 模式零副作用；safe 级 prompt/answer 只存 hash。
- 坑：debug 无鉴权、事件无 TTL、`REPLAY_ALLOW_LIVE=true` 与生产相悖。

### 稳定性
- 亮点：LLM 熔断 + fallback、Rerank OOM 熔断、HyDE/Web 优雅降级、卡死扫描、容量告警。
- 坑1：SSE 无 CLOSE 生产路径 → 队列永久驻留 → 修：生产者主动推 CLOSE + 队列 TTL。
- 坑2：LLM 无显式 timeout（默认 600s）→ 修：SDK 超时 + asyncio.wait_for + fallback。
- 金句：发现卡住 ≠ 处理卡住；软超时是产品体验问题。

### 评测
- 亮点：JSONL 数据集 + 11 规则指标 + 阈值门禁（可当 CI）+ baseline 对比。
- 坑（老实说）：数据 4 条 3 条占位；`expected_answer` 从不参与计算；无 RAGAS/Judge。
- 答法：承认没数字 → 给补齐路径（50 条真实标注 + expected_answer 接入 + 引用真实性校验）。
